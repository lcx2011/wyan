# 文言文背诵 PWA 完整版设计规格

> 历史设计记录：2026-08-10 起，存储与后端边界由 `docs/ARCHITECTURE.md` v2.0 取代；本文其余训练领域规则继续有效。

> 日期：2026-08-04  
> 状态：用户已确认  
> 基线：`docs/PRD.md` v1.1 与 `docs/ARCHITECTURE.md`

## 1. 交付范围

本次在现有 React、TypeScript、MUI、Zustand 与 Vite PWA 项目上增量交付 PRD 中 P0、P1 的全部功能。保留现有搜索、内置篇目、页面视觉语言和 PWA 构建方式，同时重构无法满足正式数据模型、状态机与测试要求的旧实现。

明确不包含 PRD 的 P2 范围：学习统计仪表盘、难度与震动设置、应用内 A–Z 键盘及通关分享图；也不包含登录、跨设备同步、社交、TTS 或用户内容上传。

## 2. 实现策略

采用增量重构，不整体重写：

1. 先建立可独立测试的领域层和正式 schema。
2. 为旧本地数据提供兼容迁移；无法可靠迁移时只重置受影响篇目。
3. 将现有页面逐步接入新领域能力和 Store。
4. 最后补齐 PWA、iOS Safari 适配及完整自动化回归。

## 3. 分层架构

### 3.1 领域层

`src/domain` 只包含纯 TypeScript，不依赖 React、DOM、网络或 localStorage：

- 内容导入：HTML 清理、标点与空白归一化、切句、卡片/段落分组。
- 内容身份：稳定句子/卡片/段落 ID、内容版本计算和版本迁移。
- 拼音：API 拼音对齐、本地拼音回退、多音字首字母集合。
- 输入引擎：目标构建、命中/错误、标点揭示、停顿、暂停/恢复、重置。
- 训练状态机：1–6 分句整卡三连、当前盲打单元错误重打与阶段恢复。
- 滚雪球调度：相邻两卡与整段单元的解锁和通过顺序。
- Boss 结算：完成/通关区分、最佳时间和幂等尝试结算。
- 复习调度：错点映射到标点分句句对、薄弱优先组题和答错隔题回插。

### 3.2 状态与持久化层

`src/stores` 持久化以下命名空间，并使用统一的 `{ schemaVersion, data }` 根结构：

- `wenyan:learning`：学习列表与完整在线篇目缓存。
- `wenyan:progress`：稳定 ID 进度、安全检查点、双层滚雪球及全文累计状态。
- `wenyan:attempts`：Boss 尝试及独立的本次结果。
- `wenyan:mistakes`：错误与停顿位置及累计次数。
- `wenyan:reviewQueue`：pending/completed 句对复习项。
- `wenyan:badges`：幂等事件与激励统计。

领域步骤结束、训练单元通过/重置、页面隐藏和路由离开时保存安全检查点。逐字输入只写内存，避免 localStorage 写放大。损坏数据只重置对应命名空间；存储配额不足时保留已有数据并阻止新增内容。

### 3.3 适配与界面层

`src/hooks` 和 `src/components` 连接领域状态机与浏览器：

- 真实、可聚焦且字号不低于 16px 的原生输入控件。
- `input`、`beforeinput`、`keydown` 与输入法组合事件适配。
- 页面隐藏、窗口失焦、系统休眠时暂停计时，恢复后重新起算停顿窗口。
- 训练错误的视觉反馈和可用时的震动增强。
- 2–3 秒临时提示，仅改变显示状态，不推进游标。
- 训练目标、进度、输入反馈和报告视图的可复用组件。

页面只负责路由参数、视图组合和用户动作，不复制领域判定。

稳定身份采用确定性算法：`contentVersion` 为规范化标题、作者、朝代、正文与译文序列的 SHA-256；句子 ID 由来源 ID、规范化句子文本及同文重复序号生成，卡片和段落 ID 由其有序成员 ID 生成。相同输入必须得到相同 ID；内容更新时先按句子 ID、再按规范化文本迁移，无法唯一匹配的部分只重置受影响篇目。

## 4. 核心数据流

### 4.1 在线篇目导入

搜索详情依次经过：结构校验、HTML 清理、文本归一化、切句、拼音对齐/回退、卡片与段落构建、稳定 ID、内容版本计算、原子持久化、追加学习列表。

API transport 通过 `VITE_API_BASE_URL` 配置基础地址；开发环境默认走 Vite `/gushiwen` 代理。生产构建不绑定特定云平台，部署方只需把该地址指向同源、无状态的反向代理；前端不得直接依赖第三方站点允许 CORS。仓库提供代理请求/响应契约和部署说明，但不引入业务后端或平台专属基础设施。

原文为空时拒绝导入且不创建占位句；译文为空时允许导入并显示“暂无译文”。只有全部阻断校验通过且本地写入成功后，页面才显示“已添加”。之后学习流程只读取本地缓存，不依赖实时 API。

### 4.2 卡片理解与三连训练

卡片理解页显示 1–6 个分句组成的整卡原文、译文、段/卡进度和前后卡导航。

每张卡统一作为一个训练目标：

```text
整卡挖空 → 整卡首字 → 整卡盲打 → 卡片通过
```

挖空和首字阶段允许错误后继续。训练盲打发生错误时记录当前期待汉字及稳定位置，短暂显示反馈，然后只重置当前盲打单元；此前通过阶段不倒退。当前单元一次运行零错误才通过。

### 4.3 双层滚雪球

段内第一张卡通过后直接进入下一张。从第二张卡开始，每张新卡通过后执行“上一卡 + 当前卡”盲打。段内最后一次两卡滚通过后，再执行完整段落盲打。

两卡滚和整段滚必须分别零错误通过并分别持久化。刷新后恢复到首个未通过单元，不重复已经通过的滚雪球单元。最后一段通过后解锁全文 Boss。

### 4.4 临时提示

提示只出现在训练盲打和滚雪球中。点击后显示当前待输入句的前 1–2 个字，并在 2–3 秒后消失。提示不调用输入处理函数，不改变 `cursor`、`revealed` 或通过判定。Boss 不提供提示。

### 4.5 Boss、报告与结算

Boss 进入 ready 状态，用户点击开始且输入控件获得焦点后进入 running。错误按键记录期待位置，但不重置全文；输入到全文末尾即 completed。

- 本次错误数大于 0：完成但未通关，可重新挑战。
- 本次错误数等于 0：完成且通关，并更新最短通过时间。
- 停顿位置不改变通关布尔值。

每次挑战生成独立 `attemptId`。报告以该尝试为事实来源，展示本次状态、用时、易错位置和停顿位置。报告结算按 `attemptId` 幂等，重复打开不能重复累计徽章、错误或复习任务。累计 `fullTextCompleted` 和 `fullTextPassed` 一旦为真不回退。

### 4.6 即时句对复习

训练/Boss 的错误和停顿按目标标点分句映射，使用 `passageId + targetClauseId` 合并位置和错误次数，生成“前分句提示 → 后分句盲打”的 pending 任务。第一分句用篇名提示，`、` 不切分。

所有 pending 任务立即可练，日期只保留给旧数据兼容和排序。进入复习页后按错误次数、重复错位、组内重试和未解决时间选最多 10 个句对或约 150 字。答错时显示完整后句，隔 2 个句对回插并要求随后连续两次无错；首次无错通过的项直接完成。

## 5. 页面与路由

- `/`：首页。存在即时 pending 句对时显示复习红点。
- `/learn`：按进行中、未开始、已完成排序的学习列表和综合进度。
- `/search`：300ms 防抖的在线/本地双通道搜索、离线降级与添加状态。
- `/passage/:passageId`：卡片理解和安全检查点恢复。
- `/passage/:passageId/challenge`：当前卡的三连训练。
- `/passage/:passageId/snowball`：两卡或整段滚雪球。
- `/passage/:passageId/exam`：全文 Boss。
- `/passage/:passageId/report/:attemptId`：Boss 报告与重试入口。
- `/review`：即时句对复习组，完成后可继续下一组。

页面沿用现有暖色 MUI 视觉语言，统一使用 iOS safe-area 间距和移动端优先布局。

## 6. 错误与降级

- 搜索断网或超时：保留并展示本地结果，明确标记在线题库不可用。
- 详情 4xx/5xx、非 JSON 或字段变化：不写入半成品，允许重试。
- 拼音无法对齐：尝试本地生成；仍失败时阻止该篇训练并指出具体句子。
- localStorage 损坏：仅重置损坏命名空间并给出非阻断提示。
- localStorage 配额不足：阻止新增篇目，保留已有数据并提示清理空间。
- Service Worker 更新：只在安全检查点提示刷新，不打断进行中的输入。
- `navigator.vibrate` 不可用：只使用视觉错误反馈，视为正常降级。
- React 渲染异常：Error Boundary 提供恢复页，避免白屏。

## 7. PWA 与 iOS Safari

Manifest 提供 192、512 和 maskable PNG 图标，设置 standalone、主题色、背景色、start URL 和 scope。Service Worker 预缓存应用壳与内置资源；在线篇目由本地数据存储离线读取。

输入控件始终位于可视区域且字号不低于 16px，底部控件使用 `env(safe-area-inset-bottom)`。进入后台、失焦或输入法组合阶段暂停停顿计时；恢复后从当前时刻重新开始，不累计后台时间。恢复输入焦点需要用户动作触发，以符合 iOS Safari 限制。

## 8. 测试与验收

引入 Vitest、Testing Library、fake timers 和 Playwright：

- 单元测试：导入、切块、稳定 ID、版本迁移、拼音、多音字、输入引擎、三连、错误重置、提示、停顿、Boss、复习调度和存储自愈。
- 组件测试：搜索状态、训练输入、错误反馈、提示自动消失、Boss 报告、复习循环、存储警告和 Error Boundary。
- E2E：在线添加、断网刷新、两句卡、训练错误重打、双层滚雪球、Boss 带错完成后零错重试、跨日/跨篇复习、后台暂停和 Service Worker 安全更新。

领域核心分支目标覆盖率 100%，项目整体语句覆盖率不低于 90%，不使用跳过测试换取覆盖率。完成前必须运行类型检查、全部单元/组件测试、生产构建和 Playwright 主流程。

真实 iOS Safari 与主屏幕 PWA 验收属于发布阻断项。当前 Windows 环境无法替代真机，因此交付同时提供真机验收清单，并将无法在本机验证的条目标明为人工验收。

## 9. 完成标准

1. PRD F01–F14 均有对应实现和可追溯测试或真机验收项。
2. 主流程从添加篇目到全文通关、报告和次日复习完整闭环。
3. 刷新、断网和页面后台切换不会丢失已通过安全检查点。
4. 本地旧数据可迁移或按篇目安全降级，不影响其他内容。
5. TypeScript、自动化测试、生产构建和本机可执行 E2E 全部通过。
6. 交付真实 iOS Safari/PWA 人工验收清单，明确本机无法替代的设备验证项。
