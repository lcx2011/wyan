# 文言文背诵 PWA 应用 PRD

> 版本：v2.0  
> 更新日期：2026-08-10  
> 状态：已确认，可作为设计与验收基线

## 1. 产品概述

### 1.1 一句话定位

一款面向中小学生的文言文渐进式背诵 PWA，通过“挖空 → 首字 → 盲打”、卡片串联、段落滚雪球、全文验收和即时句对复习，让背诵形成可持续的闯关闭环。

### 1.2 目标用户与使用环境

- 用户：初高中学生为主。
- 设备：手机、平板和电脑浏览器。
- 必须支持：iOS Safari，以及从 Safari“添加到主屏幕”后的 PWA 模式。
- 数据：无需登录，整个应用只有一份个人存档；服务端使用 SQLite 保存，浏览器保留本地镜像和断网待同步队列。
- 网络：搜索和首次添加在线篇目需要联网；已经添加并缓存的篇目可以离线学习。

### 1.3 内容来源

- 正式题库以已经接入的搜索 API 为准，标题、作者、朝代、原文、译文和拼音采用 API 返回内容。
- 应用允许保留少量内置篇目作为离线兜底；在线结果与内置结果需要明确标识。
- 在线篇目首次添加时必须转换为统一的本地 `Passage` 数据并持久化，之后学习流程不得依赖实时 API。
- 产品不建设账号、社交、权限或多用户体系；业务后端只服务这一份个人存档，并负责文章目录、学习状态和复习会话。

## 2. 已确认的产品决策

1. 篇目以搜索 API 提供的题库为正式来源，不再要求首版人工内置 30+ 篇。
2. API 返回内容作为篇目与释义的数据基准。
3. 本期不制作应用内 A–Z 键盘；iOS Safari 使用可聚焦的原生输入控件唤起系统软键盘。
4. 训练阶段的盲打发生错误时，先指出当前易错位置，再从头重打当前盲打单元；零错误才通过。
5. 每张卡无论包含多少分句，都作为一个整体完成“整卡挖空 → 整卡首字 → 整卡盲打”，不拆成逐句训练。
6. 双层滚雪球顺序已经确认：相邻两卡滚完成后，再做整段滚。
7. “提示”只临时显示 2–3 秒，不推进输入游标，也不代替输入。
8. Boss 战带错输入完全文算“完成”；只有零错误才算“通关”，完成后可再次挑战。
9. 复习不受日期门槛限制；首页进入后从待处理句对中组成一组，用户可以随时完成或继续下一组。
10. 停顿计时仅在有效输入会话内运行，页面失焦或进入后台时暂停。
11. PRD 与本文件配套的架构正文是事实来源；独立 Mermaid 图必须与正文同步。
12. iOS Safari 是正式验收平台。
13. 篇目使用内容版本号和稳定句子 ID；内容变化时迁移进度，无法迁移时只重置受影响篇目。
14. 核心逻辑、组件、完整流程、离线行为和 iOS Safari 必须接受全面测试。
15. 后端不识别用户、不校验身份；SQLite 中只有一份存档，复习会话由服务端创建并可在刷新后恢复。

## 3. 核心概念

- **句子 Sentence**：最小理解与训练内容，具有稳定 `sentenceId`。
- **卡片 Card**：学习单元，包含 1–6 个背诵分句，通常 12–30 个汉字；诗/词按韵脚/对仗/行切卡，散文按句号切句、超长句逗号二次切分。
- **段落 Segment**：进度和整段滚雪球单元，通常包含 3–4 张卡；短文允许 2–3 段，普通长文目标 4–6 段。
- **盲打单元**：一次必须零错误完成的输入目标，可以是一张卡、相邻两卡或一个完整段落。
- **完成 Completed**：用户输入到了目标末尾，允许过程中出现错误。
- **通关 Passed**：规定的盲打单元零错误完成。Boss 战的“完成”和“通关”必须分别记录。
- **易错位置**：用户按下错误首字母时，系统当时期待的目标汉字及其稳定位置；不称为“用户输入的错字”。
- **复习句对**：以标点分句为目标单位；第一分句由篇名提示，其余由紧邻前分句提示，用户盲打完整后分句。

## 4. 用户主流程

1. 首页选择“新学”。
2. 进入篇目列表，点击“添加篇目”。
3. 搜索页同时展示在线题库结果和内置兜底结果。
4. 用户选择篇目；在线篇目拉取详情、标准化、切句/卡/段并缓存到本地。
5. 用户逐卡查看原文，点击整卡展开合并后的译文。
6. 每张卡按顺序完成整卡挖空、整卡首字和整卡盲打。
7. 从第二张卡开始，每张新卡通过后执行“上一卡 + 当前卡”的两卡衔接滚。
8. 段内最后一张卡完成两卡衔接滚后，再执行整段成篇滚。
9. 所有段落通关后解锁全文 Boss 战。
10. Boss 战完成后生成报告；零错误则全文通关，否则允许再次挑战。
11. 训练/Boss 的易错位置和停顿位置映射到完整标点分句；已学但未独立盲打的分句也可低优先级进入即时复习组。

## 5. 功能需求

### 5.1 P0：核心闭环

| 编号 | 功能 | 验收标准 |
|---|---|---|
| F01 | 在线题库搜索与添加 | 输入标题、作者或关键词后搜索 API；同时提供本地结果；在线失败时本地结果仍可用；添加后的完整篇目可离线打开 |
| F02 | 内容标准化与切块 | API 原文按体裁自适应切分：散文按 `。！？；` 切句并保留标点（超长句在逗号处二次切分），诗/词按逗号/顿号/句号全分句并保留标点；每卡 1–6 个分句、通常 12–30 字；每段通常 3–4 卡；所有句、卡、段具有稳定 ID |
| F03 | 切块理解 | 卡片展示 1–6 个分句组成的连续正文；点击整卡展开去重后的 API 译文；支持前后卡切换并显示段、卡进度 |
| F04 | 整卡三连训练 | 每张卡（1–6 个分句）均作为一个目标依次完成整卡挖空 → 整卡首字 → 整卡盲打，不增加逐句训练；整卡盲打零错误才通过 |
| F05 | 拼音首字母匹配 | 用户只输入 a–z；正确时目标汉字与其后标点浮现；多音字任一允许读音均命中；错误始终有视觉反馈，支持时附加震动 |
| F06 | 双层滚雪球 | 新卡通过后进行“上一卡 + 当前卡”盲打；段末完成两卡滚后再整段盲打；两种模式都必须零错误通过 |
| F07 | 临时提示 | 仅训练盲打和滚雪球提供；点击后显示当前待输入句的前 1–2 个字，2–3 秒后消失；不改变游标、不自动填字 |
| F08 | 全文 Boss 战 | 全篇无提示输入并计时；带错输入完算完成，零错误算通关；报告展示用时、易错位置和停顿位置；未通关可重新挑战 |
| F09 | 即时句对复习 | 按“前分句提示 → 后分句盲打”检测；错误映射到完整目标分句；从训练/Boss 错点和未独立盲打分句中按优先级组成最多 10 句或约 150 字的一组；答错隔题回插并连续两次无错后移出 pending |
| F10 | 自动保存与恢复 | 篇目缓存、当前位置、各阶段、两卡滚、整段滚、Boss 状态、错题和复习状态写入本地镜像并同步到单人后端；刷新后恢复到最近安全检查点和当前复习组 |

## 6. 详细交互与判定规则

### 6.1 搜索、添加与离线

- 输入防抖 300ms 后执行本地搜索与在线搜索。
- 搜索结果区分“在线”和“内置”，相同篇目不自动合并，避免版本误判。
- 点击在线结果后拉取详情；只有通过结构校验并成功写入本地后，才显示“已添加”。
- API 缺少原文时不得生成占位学习内容，应提示“内容暂不可用”。
- API 缺少译文时可以添加，但句子释义区明确显示“暂无译文”。
- 已缓存内容断网可学习；未缓存的新内容断网不可添加。

### 6.2 卡片三连状态机

每张卡无论包含 1–6 个分句，都只有三个整卡阶段：

```text
整卡挖空 → 整卡首字 → 整卡盲打 → 卡片通过
```

- 挖空和首字阶段的错误给出反馈后可继续，不要求重做整个阶段。
- 整卡盲打、两卡滚和整段滚都是训练盲打单元。
- 训练盲打按错时：标出当前期待汉字和位置，短暂反馈后将当前盲打单元归零，从头重打。
- 只有一次运行中错误数为 0，当前训练盲打单元才通过。

### 6.3 双层滚雪球

```text
卡 1 通过
卡 2 通过 → 卡 1 + 卡 2
卡 3 通过 → 卡 2 + 卡 3
...
最后一张卡的两卡滚通过 → 整段滚 → 下一段
```

- 第一张卡不触发两卡滚。
- 两卡滚与整段滚的完成状态都持久化，刷新后无需重复已经通过的单元。
- 提示只临时展示文字；使用提示不会自动判错，但可以记录使用次数供报告或统计扩展。

### 6.4 Boss 战与报告

- 开始按钮按下且输入区获得焦点后启动计时。
- 错误按键仅做红闪/震动并记录当前期待汉字，不展示答案、不重启全文。
- 输入到全文末尾即把篇目累计状态设置为 `fullTextCompleted=true`。
- 当本次错误数为 0 时，同时设置累计状态 `fullTextPassed=true`；停顿记录本身不阻止通关。
- `fullTextCompleted/fullTextPassed` 表示“是否曾经完成/通关”，一旦为 `true` 不因后续重试失败而回退；报告中的“本次结果”由独立的 attempt 判定。
- 未通关报告提供“再次挑战”按钮，从全文开头创建新尝试。
- 最佳时间只统计已经通关的尝试，并取最短值。

### 6.5 停顿判定

- 正式输入会话开始后，当前待输入位置连续 3 秒没有有效输入，记录一次停顿。
- 每个位置在一次尝试中最多记录一次。
- 错误按键属于输入活动，会重置 3 秒计时，但仍记录错误。
- `document.hidden=true`、窗口失焦或输入法组合阶段暂停计时；恢复时从当前时刻重新开始，后台时间不累计。

### 6.6 即时句对复习

- 复习来源为训练/Boss 的易错位置、有效停顿位置，以及已经完成整卡盲打但尚未独立复现的分句。
- 任务 `status === pending` 即可练习，`dueDate` 仅保留给历史数据迁移和排序，不限制提前复习。
- 首页点击复习后，按错误次数、重复错位、组内重试次数和未解决时间计算优先级，选最多 10 个句对且目标总量约 150 字；不使用已掌握内容凑数。
- 第一分句显示篇名，其余显示紧邻前分句；`、` 不切分，关闭引号附着在分句末尾。
- 输入完整后分句的拼音首字母；目标长度不提前显示，正确字逐步浮现。
- 首次无错通过的句对立即完成；答错会显示完整后句，隔 2 个句对回插，并要求随后连续两次无错通过。
- 同一 `passageId + targetClauseId` 合并错误位置和次数；新错点会重新打开已完成项。

## 7. 页面说明

| 页面 | 核心内容 |
|---|---|
| 首页 | “复习”和“新学”两个大入口；存在即时 pending 句对时显示复习红点 |
| 新学页 | 已添加篇目，按进行中、未开始、已完成排序；显示综合进度 |
| 搜索页 | 在线/内置双通道结果、网络降级、添加状态 |
| 卡片学习页 | 当前段/卡进度、1–6 个分句原文、逐分句译文、开始训练 |
| 三连页 | 当前句、当前阶段、训练输入和错误重打反馈 |
| 滚雪球页 | 两卡或整段目标、临时提示、零错通过状态 |
| Boss 页 | 白纸式全文输入、计时器，不提供提示 |
| 报告页 | 完成/通关状态、用时、易错位置、停顿、再次挑战 |
| 复习页 | 前分句提示、后分句盲打、组内剩余数、答错完整答案和继续下一组 |

## 9. PWA 与 iOS Safari 要求

- Service Worker 预缓存应用壳、核心脚本、样式、字体和内置兜底篇目。
- 在线篇目添加成功后保存在本地数据存储并同步到 SQLite，离线时从本地读取，联网后补传。
- iOS Safari 使用真实可聚焦输入元素接收 `input`/`beforeinput`，不能只依赖全局 `keydown`。
- 输入元素保持在可视区域，避免软键盘弹出后页面异常缩放或输入焦点丢失。
- 进入后台时保存安全检查点并暂停计时；恢复后重新聚焦需由用户动作触发。
- `navigator.vibrate` 不可用是正常降级场景，视觉反馈必须始终存在。

## 10. 测试与验收

### 10.1 自动化测试

- 单元测试：API 标准化、切句/卡/段、稳定 ID、内容版本、拼音匹配、多音字、挖空、状态机、错误重置、提示计时、停顿暂停、Boss 判定、复习调度、迁移和损坏存储自愈。
- 组件测试：卡片三连、错误反馈、临时提示、报告、逾期复习、网络错误和空数据状态。
- 端到端测试：首次浏览器存档导入 → 三连 → 两卡滚 → 整段滚 → Boss 完成/通关 → 创建复习组 → 刷新恢复同一组 → 断网结果联网补传。
- PWA 测试：安装清单、Service Worker 更新、离线启动、缓存内容读取。
- 核心领域模块分支覆盖率要求 100%；项目整体语句覆盖率不低于 90%。

### 10.2 真实设备验收

- 至少一台当前主流 iPhone，在 Safari 页面模式和主屏幕 PWA 模式各走一遍完整输入流程。
- 验证软键盘输入、切后台恢复、无震动降级、离线启动和安全区布局。
- 电脑端至少覆盖最新稳定版 Chrome、Edge 和 Safari。

### 10.3 发布阻断条件
