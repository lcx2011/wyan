三、做得好的地方

✅ 选对了日志基础设施 Fastify 内置 Pino，buildApp({ logger: true }) 即获得 JSON 结构化输出、时间戳、请求 ID、级别控制，零成本吃到业界标准方案。
✅ 启动与致命错误有记录 index.ts:13 用 app.log.error(error) 记录启动失败并退出，不会"无声死亡"。
✅ 唯一业务日志点写得规范 gushiwen 代理的 info/error 两行日志使用结构化字段（upstream/status/bytes）+ 语义化事件名，是全项目日志的样板。
✅ 生产日志不会丢 systemd 托管（wenyan.service）默认把 stdout 收入 journald，journalctl -u wenyan 可查，重启策略 on-failure。
✅ 边界处理有意识 前端对后端不可用有降级与 console.warn（archive.ts:102），说明团队有"错误要留痕"的意识，只是后端没跟上。

四、问题清单（10 项）

#位置严重度问题描述
1app.ts 全部业务路由高 业务操作零日志。archive 导入/覆盖、复习会话创建/作答/完成均无任何记录：无法回答"存档什么时候被导入过""复习为什么卡住"这类问题。
2app.ts review 系列 catch高 错误被吞。attempts/complete 的 catch 只把 message 回给客户端，不记录 stack、输入参数与现场；前端若离线，故障证据为零。
3index.ts:11中 console.log 与 app.log 混用。启动日志用 console.log('[wenyan-api] listening…')，与 Pino 的 JSON 格式分属两套输出管道，生产下格式不统一。
4index.ts:7中 日志级别写死。logger: true 固定默认级别，无 LOG_LEVEL 环境变量，生产无法降噪、排障时无法开 debug。
5app.ts:33 /api/health低 健康检查污染日志。部署脚本、监控都会高频探测 health，Fastify 默认逐条打 req/res 日志，噪音大。
6deploy/wenyan.service中 无显式日志持久化策略。仅依赖 journald 兜底，容量受限、按天导出不便，且无轮转/保留期配置说明。
7src/api/* ↔ server中 无端到端请求 ID 串联。Fastify 内部有 reqId 但不透出响应头，前端报错（如 parseResponseJson 的"非 JSON 响应"）无法与服务端日志用同一 ID 关联。
8app.ts 参数校验分支低 400 无痕迹。非法 namespace、缺字段等请求只回 400，不落日志；异常/恶意请求模式不可见。
9db.ts 事务方法中 无耗时统计。better-sqlite3 同步执行，archive import 是一次大事务（bodyLimit 10MB），慢请求会阻塞事件循环，但日志里永远看不到耗时。
10tests/server/api.test.ts低 日志无回归保护。测试只断言响应，不断言日志输出，未来日志行为变化无任何测试兜底。

五、改进措施

P0统一日志基础 + 补齐业务日志半天 ~ 1 天
  • ① 抽出统一 logger 工厂 server/logger.ts：从 LOG_LEVEL 读取级别，注入服务名等基础字段，buildApp 改为接收 logger 实例而非布尔值。
  • ② 为每个业务路由补结构化日志：import/put namespace、review 三件套，统一 { event, ...fields } 事件命名，用 request.log 自动带上 reqId。
  • ③ 加全局错误处理器 setErrorHandler：5xx 打 error（含 stack），4xx 打 warn，终结"错误只回客户端不落日志"。
  • ④ 替换 console.log：index.ts 启动日志改用 app.log.info({ port, host }, 'listening')。
// server/logger.ts —— 统一日志工厂
import pino from 'pino';

export function createLogger() {
  const level = process.env.LOG_LEVEL ?? (process.env.NODE_ENV === 'production' ? 'info' : 'debug');
  return pino({ level, base: { service: 'wenyan-api' } });
}
// index.ts —— 注入实例，替换 console.log
import { createLogger } from './logger.js';
const logger = createLogger();
const app = buildApp({ logger });
await app.listen({ port, host });
logger.info({ port, host }, 'wenyan-api listening');
// app.ts —— 全局错误处理 + 业务日志示例
app.setErrorHandler((error, request, reply) => {
  if (reply.statusCode >= 500) request.log.error({ err: error }, 'request failed');
  else request.log.warn({ err: error }, 'request rejected');
  reply.send({ error: 'internal error' });
});

app.post('/api/archive/import', async (request, reply) => {
  const input = bodyRecord(request.body);
  const started = performance.now();
  try {
    const result = database.importArchive(/* ... */);
    request.log.info({
      event: 'archive.import',
      namespaces: Object.keys(bodyRecord(input.namespaces ?? {})),
      durationMs: Math.round(performance.now() - started),
    }, 'archive imported');
    return reply.send(result);
  } catch (error) {
    request.log.error({ err: error, event: 'archive.import' }, 'archive import failed');
    throw error;
  }
});

注意：import 的 body 是用户完整存档，日志里只记 namespace 清单与耗时，不要记录 body 内容（避免大对象与潜在隐私）。

P1生产可运维性：持久化、串联、降噪1 ~ 2 天
  • ⑤ 日志落盘 + 按天轮转：引入 pino-roll 写 data/logs/server.log，保留 7 天；systemd 下 journalctl -u wenyan 作为兜底，文档写明两者用法。
  • ⑥ 透出 X-Request-Id：hook 把 Fastify 的 request.id 写入响应头；前端 fetch 封装读取它并拼进错误信息，排障时前端报错与服务端日志一键关联。
  • ⑦ health 降噪：用 Fastify 的 autoLogging.ignore 跳过 /api/health 的访问日志。
// app.ts —— 请求 ID 透出 + health 降噪
app.addHook('onSend', async (request, reply) => {
  reply.header('x-request-id', request.id);
});

const app = Fastify({
  logger: {
    level: process.env.LOG_LEVEL ?? 'info',
    autoLogging: { ignore: (req) => req.url === '/api/health' },
  },
  bodyLimit: 10 * 1024 * 1024,
});
// src/api/archive.ts —— 前端读取并透传请求 ID
const response = await fetch(url, init);
const requestId = response.headers.get('x-request-id');
if (!response.ok) throw new Error(`archive request failed: ${response.status} (reqId=${requestId ?? 'n/a'})`);
P2可观测性进阶（按需）按需迭代
  • ⑧ 慢操作告警：对 archive import/put、复习事务做耗时统计，超过阈值（如 500ms）打 warn，提前发现事件循环阻塞。
  • ⑨ 生命周期日志：启动时记录版本号、DB 路径、内置篇目数、迁移结果；优雅关闭时记录。
  • ⑩ 错误码与字段规范：响应体带 error.code，日志字段统一 snake_case、事件名 module.action，为将来接日志平台（如 Loki/ELK）铺路。
  • ⑪ 测试补日志断言：用 app.inject + 可收集的 pino transport，断言关键事件（import 成功、attempt 冲突）确实产生日志。
